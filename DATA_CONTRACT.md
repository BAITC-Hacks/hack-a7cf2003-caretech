# EKT: контракт данных товара для MVP

Версия: 23.09.2026. Основано на переданных примерах ответа списка товаров и `GET https://ekt.kz/api/products/detail?id=515291`. Это снимок примера, а не обещание актуальной цены или остатка.

## Для чего этот файл

Backend получает сырой ответ EKT и преобразует его в объект `Product` для поиска, карточки товара и ответа ассистента. Список `/api/products` содержит краткие сведения; перед ответом о наличии, технических характеристиках или добавлением в корзину нужно получить актуальную карточку `/api/products/detail?id={id}`. Пример результата: [sample_product.json](sample_product.json).

## Источники и поля

| Поле `Product` | Поле EKT | Тип в нашем JSON | Правило |
|---|---|---|---|
| `id` | `id` | integer | ID товара; не путать с артикулом |
| `article` | `article` | string или null | Внутренний артикул, **сохранить завершающий `_`** |
| `supplier_article` | `properties.ARTIKULPOSTAVSHCHIKA` | string или null | Артикул поставщика; отдельное поле |
| `name` | `name` | string | Название без выдуманного дополнения |
| `description` | `description` | string или null | Текст карточки, пробелы и переводы строк можно нормализовать |
| `price` | `price` | number или null | Цена из свежего `detail`; валюта в показанном JSON не указана, уточнить перед отображением символа |
| `quantity` | `quantity` | integer или null | Общий остаток из свежего `detail`; `null` означает неизвестно |
| `available_stores` | `stores[]` | array | Сохранять `id`, `name`, `quantity` у складов с количеством > 0; перечень не равен автоматически доступному для продажи остатку |
| `brand` | `properties.TORGOVAYA_MARKA` | string или null | Торговая марка |
| `product_type` | `properties.OBYEM` | string или null | В показанном примере тип товара; проверить на других карточках перед общим правилом |
| `category` | отсутствует как отдельное поле | null или string | Не выдавать сегменты `url` за подтверждённую категорию; можно добавить только при наличии надёжного источника |
| `characteristics.poles` | `properties.KOLICHESTVO_POLYUSOV` | string или null | Сохранять как текст источника |
| `characteristics.current` | `properties.NOMINALNYY_TOK` | string или null | При конфликте с `name`/`description` установить `null` и записать конфликт |
| `characteristics.voltage` | `properties.NOMINALNOE_NAPRYAZHENIE` | string или null | Сохранять единицу измерения |
| `characteristics.breaking_capacity` | `properties.NOMINALNAYA_OTKLYUCHAYUSHCHAYA_SPOSOBNOST` | string или null | Сохранять единицу измерения |
| `characteristics.installation_type` | `properties.TIP_USTANOVKI` | string или null | Указывать только если присутствует |
| `related_product_ids` | `properties.RECOMM` | array of integers | Предположительно связанные товары; это **не подтверждённые аналоги** |
| `minimum_multiple` | `properties.KRATNOST_MIN` | integer или null | Кратность из карточки, не заменяет правила покупки |
| `certificate_urls` | в данном ответе отсутствует | array или null | `null` = неизвестно, `[]` = источник проверен и сертификатов нет; пока `null` |
| `image` | `image` | string или null | URL изображения |
| `url` | `url` | string или null | URL карточки EKT |
| `data_issues` | проверка разных полей | array of strings | Короткие явные сообщения о конфликте или нарушении целостности |

`offers` в обоих предоставленных примерах пустой. Сохранять исходные нестандартные `properties` при необходимости можно внутри backend, но не превращать их автоматически в проверенные характеристики. Для списка товаров `quantity`, `stores`, `description`, `properties` неизвестны: отсутствие в списке **не означает нулевой остаток**.

## Преобразование и проверки

1. Находить товар по точному `id`, `article` или `supplier_article` прежде поиска по названию. Не удалять `_` и ведущие нули у артикулов. Если совпадений несколько, предложить уточнить выбор.
2. Для данных карточки отображать только подтверждённые значения. Если поле отсутствует или ответ `detail` недоступен, использовать `null` и сообщать «нет данных», а не подставлять `0`/пустую строку как будто это факт.
3. `quantity > 0` означает заявленный общий остаток; `quantity === 0` — нет по этому ответу API; `quantity === null` — статус неизвестен. Проверять свежий `detail` перед конкретным обещанием и действием с корзиной.
4. Показывать склады с положительным остатком. Сверять сумму остатков по всем складам с общим `quantity`; при расхождении записывать `data_issues` и не обещать доступность в конкретном складе без проверки. Наличие на складах с названиями вроде «Брак» не считать автоматически пригодным к продаже.
5. Характеристики, названные в нескольких местах, сравнивать с учётом пробелов и единиц. При разных значениях сохранять конфликт и не озвучивать спорное значение как установленный факт. Правило «всегда брать `properties`» здесь небезопасно.
6. Для аналога сначала получить `detail` кандидата и проверить положительный остаток, назначение/тип и существенные параметры. `RECOMM` может дать кандидатов, но само поле не подтверждает взаимозаменяемость. Объяснение аналога должно опираться только на совпадающие проверенные характеристики; при конфликте номинального тока автоматическую рекомендацию не делать.
7. Перед добавлением в корзину backend повторно проверяет цену, остаток и допустимое количество и ждёт **явного подтверждения** пользователя. Никакой текст из кэша или ответ LLM не является разрешением изменить корзину. Корзину изменяет интеграция сайта.

## Известная проблема качества: ID 515291

| Источник | Номинальный ток |
|---|---|
| `name` | 160 А |
| `description` | 160 А |
| `properties.NOMINALNYY_TOK` | 250 А |

Поэтому в образце `characteristics.current = null`; исходные значения перечислены в `data_issues`. Разрешить конфликт можно только после проверки карточки или подтверждения партнёра. Остатки положительных складов в переданном образце суммируются в 23 и совпадают с `quantity = 23`.

## Что ещё нужно получить для требований кейса

- Источник сертификатов: в карточке ID 515291 ссылка на сертификат не показана; нельзя объявлять, что сертификата у товара нет.
- Подтверждённые правила оплаты, доставки и минимальной партии: в примере товара их нет; ассистенту нужен отдельный согласованный FAQ/источник.
- Реальные ID товара с `quantity = 0` и проверенного аналога для демонстрации: эти ID нельзя вывести из предоставленных страниц списка.
- Правила доступных для продажи складов и валюта цены: подтвердить у партнёра/разработчика интеграции.

## Минимальная проверка преобразования

Для ID 515291 ожидать `id = 515291`, `article = "200300285_"`, `supplier_article = "027228"`, `price = 64920`, `quantity = 23`, семь положительных складов с суммой 23, `related_product_ids = [48783, 23466, 28727]`, `characteristics.current = null` и запись о конфликте. Открытие ID 515291 через список и через `detail` должно давать один и тот же ID.
